## Trust and supply chain security

SBOMs describe what is present. These resources help establish where software came from and whether it was changed.

<CardGrid>
    <BrandCard title="SLSA" icon="community">
        <span id="ref-slsa" />
        A framework for improving and communicating the integrity and provenance of software builds.
        <a href="https://slsa.dev/" target="_blank" rel="noopener noreferrer">Visit SLSA</a>
    </BrandCard>
    <BrandCard title="Sigstore" icon="community">
        <span id="ref-sigstore" />
        Tools and services for signing software artifacts and verifying who produced them.
        <a href="https://www.sigstore.dev/" target="_blank" rel="noopener noreferrer">Visit Sigstore</a>
    </BrandCard>
    <BrandCard title="in-toto" icon="community">
        <span id="ref-in-toto" />
        A framework for recording and verifying the steps that happen in a software supply chain.
        <a href="https://in-toto.io/" target="_blank" rel="noopener noreferrer">Visit in-toto</a>
    </BrandCard>
    <BrandCard title="OWASP Dependency-Track" icon="tooling">
        <span id="ref-dep-track" />
        An open source platform for ingesting SBOMs and monitoring components for vulnerabilities and policy issues.
        <a href="https://dependencytrack.org/" target="_blank" rel="noopener noreferrer">Visit Dependency-Track</a>
    </BrandCard>
    <BrandCard title="CycloneDX Attestations" icon="framework">
        <span id="ref-cdxa" />

        <a href="https://cyclonedx.org/capabilities/attestations/" target="_blank" rel="noopener noreferrer">Read about CDXA</a>

</CardGrid>
